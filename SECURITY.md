# Security Policy

## Reporting a vulnerability

Please report security vulnerabilities by e-mail to **security@cybedefend.com**.

**Never report a vulnerability in a public issue, a pull request, a discussion or any other public channel.**

Please include, as far as you can:

- the affected component and version (the release tag, or the commit);
- a description of the vulnerability and its impact;
- the steps to reproduce it, or a proof of concept;
- any known mitigation;
- how you would like to be credited, if at all.

## What to expect

- **Acknowledgement:** we acknowledge your report within **3 working days**.
- **Assessment:** we confirm whether the issue is a vulnerability, assess its severity and keep you informed of our progress.
- **Coordinated disclosure:** we aim to fix the vulnerability and disclose it within **90 days** of your report. We agree the disclosure date with you, and we ask you not to disclose the vulnerability before that date.
- **Credit:** with your permission, we credit you in the release notes.

## How fixes are released

Fixes follow an embargo. A security fix is deployed to CybeDefend Cloud first, and published to this repository on the disclosure day, together with the release notes that describe the vulnerability. Until that day, the fix does not appear in this repository.

## Supported versions

Only the **latest release** receives security fixes. Please upgrade to the latest release before reporting, and check whether the issue still occurs there.

| Version | Supported |
|---|---|
| Latest release | Yes |
| Any earlier release | No |
